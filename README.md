# SillyTavern Auto Rewrite

一个支持手动与自动重写的 SillyTavern UI 扩展，不需要修改酒馆本体，不依赖其他第三方扩展。

## 工作方式

点击最新角色回复正文最底部的“重写”，或开启自动重写。扩展等待酒馆结束生成和保存，然后临时追加修改意见作为普通用户消息，再通过酒馆原生生成入口生成一次新回复。请求中聊天历史的次序是：

```text
user: 本轮要求
assistant: 第一版正文
user: 修改意见：请重写上一条，不要续写……
assistant: 第二版正文
```

生成时只把这些内容作为普通聊天交给当前预设处理，不重排最终 API 请求。完成后收回临时用户消息与新楼，将第二版放回原稿所在楼层，原稿保存为该楼的旧版本；默认显示重写版。界面不会永久新增两楼。扩展自身不会继续触发第三轮。

正文底部操作栏提供“重写”“查看原稿／返回重写版”、自动开关和设置入口。在原稿与重写版之间切换只使用已保存的版本，不会发出模型请求。多次重写保留已有版本，并记住所基于的原稿。

## 安装与使用

在酒馆“扩展 → 安装扩展”中填写：

```text
https://github.com/wujimol/SillyTavern-Auto-Rewrite
```

也可将源码中的 `index.js`、`revisions.js`、`ui.js`、`manifest.json`、`style.css` 放进一个扩展目录，安装到酒馆的用户扩展目录或 `public/scripts/extensions/third-party/auto-rewrite`。刷新页面，点击正文底部的设置图标，或在扩展设置中展开“正文重写 · 独立版”，填写修改意见。自动重写默认关闭；关闭自动时仍可手动重写最新回复。

与旧定制版替换到同一个目录时，沿用已有的自动开关和修改意见。安装到新目录时，应先禁用旧的重写扩展，避免两个扩展同时自动生成。

## 范围

- 手动按钮、自动开关、修改意见与原稿快捷切换；使用酒馆当前的连接、模型和预设。
- 点击时锁定当前显示版本；翻页、保存或生成尚未完成时不发起另一次重写。
- 支持普通生成、重新生成和右箭头生成的新版本；只翻阅旧版本不会触发。
- 仅支持单角色聊天；不自动重写开场白、后台请求或没有正文的回复。
- 输入框有草稿、待发送附件或消息正在编辑时暂缓；发送新消息或切换上下文会取消旧队列。
- 使用酒馆原有停止按钮。停止或失败后清理本次临时消息，保留原稿，不自动重试。
- 同一标签页刷新中断时，使用会话内的操作凭据检查并恢复未完成重写；若聊天已新增用户消息或原稿发生变化，则保留记录，不擅自覆盖。
- 关闭自动开关只取消尚未开始的队列；已经发出的第二轮可用原生停止按钮取消。

## 预设兼容

扩展不编辑预设，不重排最终 API 请求，不直接调用模型接口，不使用自定义 `Generate()` 参数，不拦截 `fetch`，也不解析预设的工具协议。修改意见在请求期间是正常的用户消息，之后仍由酒馆及现有预设执行上下文处理、世界书、正则、工具调用与防截断逻辑。请求完成后只整理本次已确认归属的临时消息，早期聊天记录不重排。

这保留原生处理路径，但不能保证所有预设都兼容。预设可能主动删除历史正文、限制上下文、忽略修改意见或在第一轮就写入变量和总结；扩展不会撤销这些副作用。模型是否分段返回也由模型与渠道决定。

## 实现与验证状态

使用官方 `release` 分支可见的上下文、生成事件、聊天渲染和普通生成接口。等待 `streamingProcessor` 被酒馆释放后再开始第二轮，避免依赖定制版的收尾标记。

3.0 调整为同楼替换，2.0 已经产生的普通聊天记录不会被批量迁移或删除。

当前版本完成了源码接口对照，未运行自动测试、构建、浏览器回归或真实模型请求；尚未声称已在原版酒馆上完成运行验证。
